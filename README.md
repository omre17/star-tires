# Star Tires — מערכת מלאי, נוכחות ואומדן שכר

מערכת Full-Stack פעילה ב-Flask + SQLite עם ממשק עברי רספונסיבי, הרשאות מנהל/עובד,
ניהול מלאי, נוכחות, אומדן שכר ועוזר Ollama אופציונלי. כל הפעולות ביישום Flask
נבדקות בצד השרת ונשמרות במסד הנתונים; `docs/` הוא דמו סטטי נפרד למגייסים.

## דמו חי למגייסים

**[פתיחת הדמו האינטראקטיבי](https://star-tires-ops-demo.khetomre.chatgpt.site)**

הדמו נפתח ישירות ללא התקנה או התחברות ומאפשר לעבור בין תצוגת מנהל לעובד,
לעדכן מלאי, לדווח נוכחות, לצפות באומדן שכר ולהתנסות בעוזר המדומה.
הוא פועל בצד הדפדפן עם נתונים פיקטיביים בלבד. קוד הדמו נמצא תחת `docs/`,
וקוד ה-Flask המלא נשאר המקור שמדגים את צד השרת, SQLite, הרשאות ואבטחה.

## יכולות מרכזיות

- סיסמאות מגובבות באמצעות Werkzeug; ללא סיסמאות ברירת מחדל בקוד.
- מפתח חתימת Session מחוץ לקוד, בדיקת תפקיד מול מסד הנתונים בכל בקשה.
- CSRF בכל טופס POST, התנתקות, תפוגת Session, כותרות אבטחה והגבלת גודל בקשה.
- הגבלת ניסיונות כניסה, פעולות כתיבה ובקשות AI במסד הנתונים, גם בריבוי workers.
- אימות קלט מלאי, איסור כמות שלילית ומגבלת כמות כוללת. כמו בגרסה המקורית, הפעולה היא **הוספה למלאי**, לא מכירה/הפחתה.
- רצף כניסה/יציאה תקין עם נעילה טרנזקציונית; רענון אחרי POST לא משכפל פעולה.
- פונקציה אחת לחישוב שעות לכל הדוחות; חישוב שבועי אמיתי, כולל חיתוך משמרת בגבול השבוע.
- עובד אינו מקבל מלאי דרך ה-AI. שגיאות חיבור לא חושפות כתובות פנימיות.
- נתוני דמו נפרדים, הוראות הרצה ובדיקות אוטומטיות.

## הרצת מערכת ה-Flask המלאה ב-Windows / CMD

חלץ את ה-ZIP לתיקייה חדשה. אל תחליף את הפרויקט הישן לפני ששמרת גיבוי.
פתח CMD בתיקייה שבה נמצא `app.py`. נדרשת Python 3.11 ומעלה.

```bat
py -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
set DEMO_MODE=0
set AI_ENABLED=0
python -m flask --app app:create_app init-db
python -m flask --app app:create_app create-user
python -m flask --app app:create_app run
```

פקודת `create-user` מבקשת שם משתמש, תפקיד וסיסמה של 12 תווים לפחות.
צור חשבון מנהל וחשבון עובד, פתח http://127.0.0.1:5000 והתחבר.
הנתונים נשמרים כברירת מחדל ב-`instance/star_tires.sqlite3`.
בפתיחת CMD חדש יש להפעיל שוב את הסביבה הווירטואלית.

ב-PowerShell הגדרת משתנה נעשית כך: `$env:DEMO_MODE="0"`.
ב-macOS/Linux: `python3 -m venv .venv`, לאחר מכן `source .venv/bin/activate`
ו-`export DEMO_MODE=0`; יתר פקודות Python זהות.

## הרצה מקומית עם נתוני דוגמה

לבדיקה מהירה בלבד אפשר להגדיר `DEMO_MODE=1`, להריץ `init-db` ואז `seed-demo`.
מצב זה יוצר משתמשי דוגמה ומציג כפתורי כניסה ללא סיסמה. אין להשתמש בו עם מידע אמיתי.

## סיור קצר במערכת

1. מנהל דמו: צפה במלאי, הוסף כמות לסוג צמיג וצפה בדוח השכר.
2. התנתק והיכנס בחשבון עובד: צפה בדוח אישי, התחל וסיים עבודה.
3. כפתור כניסה כפולה מושבת; גם שליחה ישירה נחסמת בצד השרת.
4. פתח את עוזר ה-AI: ללא שירות Ollama תופיע הודעה מפורשת שהוא כבוי.

חשבונות הדמו משותפים לכל המבקרים: שינוי של מבקר אחד נראה לאחרים.
אין להזין בהם נתונים אמיתיים. אין בממשק כפתור לאיפוס או למחיקת מסד.
אם הדמו מתמלא, עצור את השירות ובחר `DATABASE_PATH` חדש, ואז אתחל וזרע אותו.
בשרת מאחורי proxy הגבלת הכניסה לפי IP עלולה לחול על כל המבקרים יחד;
בכוונה אין אמון אוטומטי ב-X-Forwarded-For. יש להגדיר proxy אמין בהתאם למארח.

## ניהול חשבונות

במסד נפרד עם `DEMO_MODE=0` הרץ `init-db`, ואז:

```text
python -m flask --app app:create_app create-user
```

תתבקש להזין שם, תפקיד וסיסמה של 12 תווים לפחות. זהו כלי CLI למנהל המערכת;
אין כאן מסך לניהול/עריכת עובדים. אין מנגנון שחזור סיסמה בדוא"ל.

## AI אופציונלי

התקן והריץ Ollama בסביבה שלך וטען מודל מתאים, למשל `ollama pull llama3`.
הגדר `AI_ENABLED=1`, ובמידת הצורך `OLLAMA_URL` ו-`OLLAMA_MODEL`, והפעל מחדש את Flask.
הכתובת מוגדרת בשרת, לעולם לא מתוך טופס משתמש. אל תחשוף את Ollama ישירות לאינטרנט.
בפריסה מרוחקת localhost מציין את השרת, לא את המחשב האישי שלך.
מגבלות: 5 בקשות לדקה לחשבון, 20 לדקה בכלל המערכת, עד 1000 תווי שאלה ו-300 טוקני תשובה.
העוזר קורא הקשר בלבד ואינו מפעיל פקודות או משנה נתונים. אין ערובה לדיוק התשובות.

## פריסה באינטרנט — הכנה, לא פריסה שבוצעה

המערכת דורשת שרת Python; GitHub Pages אינו מתאים לצד Flask.

1. התקן `requirements.txt` בסביבת Linux/Python הנתמכת אצל המארח.
2. הגדר `APP_ENV=production`, `DEMO_MODE=0`, `AI_ENABLED=0`.
3. צור מפתח באמצעות `python -c "import secrets; print(secrets.token_hex(32))"`
   והגדר אותו כ-`SECRET_KEY` במשתני הסביבה של המארח. אין להכניס אותו למאגר.
4. הגדר `DATABASE_PATH` לנתיב SQLite על **דיסק מתמשך**.
5. באותה סביבה ובאותו דיסק הרץ `init-db` ולאחר מכן `create-user` לכל חשבון ראשוני.
6. הפעל ב-Linux: `gunicorn 'app:create_app()' --bind 0.0.0.0:$PORT --workers 2 --timeout 60`.
7. HTTPS חובה: במצב production עוגיות נשלחות רק בחיבור מאובטח.
8. בדוק את שני התפקידים, כתיבה והתמדה אחרי הפעלה מחדש, ואז הוסף לקורות החיים קישור.

ה-Procfile מספק פקודת הפעלה בלבד; הוא אינו יוצר דיסק או מגדיר את המשתנים אצל המארח.
SQLite כאן מתאים לדמו קטן על שרת אחד עם דיסק מקומי מתמשך. אין להפעיל כמה replicas
עם מסדים נפרדים או SQLite על מערכת קבצים רשתית. להרחבה נדרשת התאמת מסד/תשתית.
במצב production האפליקציה מסרבת לעלות ללא מפתח. בפיתוח נוצר מפתח מקומי ב-`instance/`.
`.env.example` הוא תיעוד בלבד; האפליקציה אינה טוענת אוטומטית קובצי `.env`.

## הנתונים המקוריים

הארכיון החדש אינו מכיל את `database.db` המקורי או מידע אמיתי. הקובץ המקורי לא שונה.
ברירת המחדל החדשה היא `instance/star_tires.sqlite3`. אין להעתיק אליו את המסד הישן:
הסכמה השתנתה, והקוד מסרב לאתחל מסד שמכיל את עמודת הסיסמה הישנה.
העברת נתונים אמיתיים דורשת תהליך הגירה נפרד לאחר גיבוי ובדיקת הרשומות.
אם המסד הישן או סיסמאות אמיתיות כבר פורסמו ב-GitHub, הוספת `.gitignore` אינה
מוחקת אותם מההיסטוריה. יש להחליף סיסמאות שנחשפו ולהסיר מידע רגיש מהמאגר ומההיסטוריה.

## מגבלות מכוונות

- זמני התצוגה ב-UTC; השבוע מתחיל ביום ראשון לפי UTC. אין עדיין התאמת שעון ישראל/DST.
- דוח השכר הוא אומדן לכל התקופה לפי התעריף הנוכחי ומשמרות שהושלמו בלבד.
  הוא אינו מחשב שעות נוספות, מסים, זכויות או תעריפים היסטוריים.
- אין כאן מכירות, קבלות, תיקון משמרת ידני, ניהול עובדים מלא או audit log.
- ממשק Flask מבוסס Jinja, HTML ו-CSS; הדמו הסטטי תחת `docs/` משתמש גם ב-JavaScript.

## מבנה

`app.py`: הגדרות, אימות והרשאות, routes, CLI וגישת מסד.
`services.py`: חישובי שעות משותפים.
`templates/`: ממשק עברי רספונסיבי ו-CSRF. `static/app.css`: העיצוב המלא של מערכת Flask.
`tests/`: בדיקות. `requirements*.txt`: תלותי ריצה ופיתוח.
`docs/`: דמו סטטי ואינטראקטיבי המוכן גם לפרסום ישיר ב-GitHub Pages.
